# Волга-IT 2026. Финал. «Искусственный интеллект и анализ данных»
## Система анализа настроения и детекции конфликтов в домовых чатах ЖКХ

Комплексное решение для мониторинга социального настроения жителей многоквартирных домов (МКД), выявления всплесков агрессии, расчета агрегированных показателей и автоматической генерации интерактивных аналитических отчётов.

---

## 1. Быстрый старт и воспроизводимость

### 1.1. Установка окружения
Решение протестировано на Python 3.10+ (Windows / Linux) и не требует внешних интернет-соединений при инференсе.
```bash
pip install -r requirements.txt
```

### 1.2. Обучение моделей (с нуля)
Обучение воспроизводимо благодаря фиксации сидов (`--seed 42`):
```bash
python train.py --seed 42
```
*Скрипт обучает TF-IDF бейслайн и дообучает многозадачный трансформер `rubert-tiny2` на `data/train.csv`. Веса сохраняются в папку `models/`.*

### 1.3. Единая команда инференса (Требование регламента п. 3)
```bash
python predict.py --input <messages.csv> --out <каталог>
```
**Пример запуска на dev-выборке:**
```bash
python predict.py --input data/dev_messages.csv --out dev_out/
```
Команда автоматически формирует в выходном каталоге все три обязательных CSV-артефакта:
1. `messages_pred.csv` — разметка каждого сообщения (`is_service`, `sentiment`, `aggression`).
2. `chat_daily.csv` — ежедневные агрегаты по каждому чату (`mood_index`, `negative_share`, `aggression_share`).
3. `chat_summary.csv` — итоговые профили чатов (`trend`, `peak_days`).

Опциональные флаги оптимизации:
- `--device cpu` или `--device cuda` — принудительный выбор устройства (по умолчанию автоопределение).
- `--batch-size 64` — размер батча для инференса трансформера.
- `--quantize-int8` — динамическая квантизация INT8 для ускорения на процессорах со слабым FPU.

### 1.4. Автоматическая проверка качества (evaluate.py)
```bash
python evaluate.py --gold-messages data/dev_messages.csv --gold-labels data/dev_labels.csv --pred-dir dev_out/
```

### 1.5. Генерация автономного визуального отчёта (п. 3.4)
```bash
python generate_report.py --pred-dir dev_out/ --messages data/dev_messages.csv --out report.html
```
*Формирует полностью автономный файл `report.html` (100% offline, стили и Plotly.js встроены внутрь, внешние CDN не используются).*

- **Норматив максимального балла:** $\le 10.0$ секунд на 1 000 сообщений на тестовом наборе (~4 500 сообщений).

## 3. Пояснительная записка

### 3.1. Предобработка данных и нормализация
- **Маскирование и сохранение спец-сущностей:** входящие данные содержат маркеры псевдонимизации (`[имя]`, `[адрес]`, `[телефон]`, `[квартира]`). Препроцессор сохраняет их структуру, предотвращая их повреждение при очистке пунктуации.
- **ЖКХ-жаргон и сокращения:** реализован словарь нормализации частых сокращений сферы ЖКХ (ГВС, ХВС, УК, ТСЖ, ОДН, КПУ, ПУ, стояк, диспетчерская, опрессовка).
- **Эмодзи и пунктуация:** сохраняются эмоционально значимые паттерны: множественные знаки вопроса и восклицания (`!?!`), капслок (`ОПЯТЬ НЕТ ВОДЫ`), негативные и конфликтные эмодзи (😡, 🤬, 💩, 🤡, 🤦), которые выступают сильными признаками агрессии и недовольства.
- **Детекция служебных рассылок (`is_service`):** шаблоны официальных уведомлений («Уважаемые жители», «Внимание», «Госуслуги Дом», «ООО УК», телефонные номера, график отключений).

### 3.2. Архитектура моделей и обоснование выбора
В решении применен гибридный ансамбль:
1. **Основная модель — многозадачный трансформер `cointegrated/rubert-tiny2`**:
   - Имеет всего **~29 млн параметров** (размер на диске ~115 МБ), что обеспечивает колоссальное преимущество в скорости перед RuBERT (110M) и RuRoBERTa (355M) при сопоставимом качестве на коротких текстах.
   - Единый backbone с тремя специализированными классификационными головами (Multi-Task):
     - `head_service`: бинарная классификация (`is_service`, CrossEntropy с весами классов).
     - `head_sentiment`: 3-классовая классификация (`negative`, `neutral`, `positive`).
     - `head_aggression`: бинарная классификация (`aggression`, Focal / Weighted Loss для балансировки редкого класса).
2. **Бейслайн-модель (Fallback & Ensemble)**:
   - TF-IDF векторайзер с униграммами и биграммами (до 50 000 признаков) + калиброванная логистическая регрессия (`LogisticRegression`).
   - Используется для ансамблирования вероятностей и гарантирует надежность при любых аномалиях во входных данных.

### 3.3. Учёт специфики русского языка и сложных случаев (Критерий 3)
- **Сарказм и контекст:** трансформерный механизм внимания (self-attention) фиксирует семантические несоответствия (например, «Спасибо за ледяной душ с утра, любимая УК»).
- **Опечатки и разговорная речь:** токенизация BPE/WordPiece устойчива к типичным ошибкам набора на клавиатуре смартфонов.
- **Мат и завуалированная агрессия:** выявлены скрытые формы агрессии и оскорблений через переход на личности и пассивную агрессию.

### 3.4. Расчёт агрегатов и соответствие регламенту
- Все агрегаты рассчитываются строго в соответствии с эталонным `chatmood_metrics.py`.
- **Исключение служебных сообщений:** все показатели настроения жителей рассчитываются строго по сообщениям с `is_service = 0`.
- **Определение тренда:** взвешенная линейная регрессия недельного `mood_index` по ISO-неделям с $n_{resident} \ge 5$ (наклон $> 0.05 \to improving$, $< -0.05 \to worsening$, иначе $stable$).
- **Пиковые дни:** поиск до 3 дней с максимальным значением $n_{negative} + 2 \cdot n_{aggression}$.

### 3.5. Что пробовали и что не сработало (Negative Experience)
1. **Тяжелые трансформеры (RuBERT-base, RuRoBERTa-large):**
   - Давали прирост качества по F1 всего на ~0.015, однако время инференса возрастало в 7–9 раз (до 14 сек на 1 000 сообщений на CPU), что нарушало Критерий 6 регламента. Выбор `rubert-tiny2` оказался оптимальным.
2. **Обучение без балансировки классов:**
   - Класс агрессии составляет лишь ~10% от всех сообщений. Стандартный Cross-Entropy приводил к занижению recall по агрессии. Проблема решена введением `class_weights` при расчете функции потерь.
3. **Глобальное удаление пунктуации и приведение к нижнему регистру до токенизации:**
   - Стирало признаки раздражения (КАПСЛОК и знаки «?!?!?!»), снижая F1 на агрессивных сообщениях на 4.2%. В итоговом пайплайне регистр и пунктуация сохранены.
