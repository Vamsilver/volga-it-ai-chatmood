# Волга-IT 2026. Финал. «Искусственный интеллект и анализ данных»
## Система анализа настроения и детекции конфликтов в домовых чатах ЖКХ

Комплексное решение для мониторинга социального настроения жителей многоквартирных домов (МКД), выявления всплесков агрессии, расчета агрегированных показателей и автоматической генерации интерактивных аналитических отчётов.

## 1. Быстрый старт и воспроизводимость

### 1.1. Установка окружения
Решение протестировано на Python 3.10+ (Windows / Linux) и не требует внешних интернет-соединений при инференсе.
```bash
pip install -r requirements.txt
```

### 1.2. Обучение моделей (с нуля)
Обучение воспроизводимо благодаря фиксации сидов (`--seed 42`):
```bash
python train.py --seed 42
```
*Скрипт обучает TF-IDF бейслайн и дообучает многозадачный трансформер `rubert-tiny2` на `data/train.csv`. Веса сохраняются в папку `models/`.*

### 1.3. Единая команда инференса (Требование регламента п. 3)
```bash
python predict.py --input <messages.csv> --out <каталог>
```
**Пример запуска на dev-выборке:**
```bash
python predict.py --input data/dev_messages.csv --out dev_out/
```
Команда автоматически формирует в выходном каталоге все три обязательных CSV-артефакта:
1. `messages_pred.csv` — разметка каждого сообщения (`is_service`, `sentiment`, `aggression`).
2. `chat_daily.csv` — ежедневные агрегаты по каждому чату (`mood_index`, `negative_share`, `aggression_share`).
3. `chat_summary.csv` — итоговые профили чатов (`trend`, `peak_days`).

Опциональные флаги оптимизации:
- `--device cpu` или `--device cuda` — принудительный выбор устройства (по умолчанию автоопределение).
- `--batch-size 64` — размер батча для инференса трансформера.
- `--quantize-int8` — динамическая квантизация INT8 для ускорения на процессорах со слабым FPU.

### 1.4. Автоматическая проверка качества (evaluate.py)
```bash
python evaluate.py --gold-messages data/dev_messages.csv --gold-labels data/dev_labels.csv --pred-dir dev_out/
```
*В соответствии с **п. 6.3 регламента**, официальный текстовый вывод скрипта зафиксирован в файле [`dev_out/evaluate_output.txt`](dev_out/evaluate_output.txt).*

### 1.5. Генерация автономного визуального отчёта (п. 3.4)
```bash
python generate_report.py --pred-dir dev_out/ --messages data/dev_messages.csv --out report.html
```
*Формирует полностью автономный файл `report.html` (100% offline, стили и Plotly.js встроены внутрь, внешние CDN не используются).*

## 4. Пояснительная записка

### 4.1. Предобработка данных и нормализация
- **Маскирование и сохранение спец-сущностей:** входящие данные содержат маркеры псевдонимизации (`[имя]`, `[адрес]`, `[телефон]`, `[квартира]`). Препроцессор сохраняет их структуру, предотвращая их повреждение при очистке пунктуации.
- **ЖКХ-жаргон и сокращения:** реализован словарь нормализации частых сокращений сферы ЖКХ (ГВС, ХВС, УК, ТСЖ, ОДН, КПУ, ПУ, стояк, диспетчерская, опрессовка).
- **Эмодзи и пунктуация:** сохраняются эмоционально значимые паттерны: множественные знаки вопроса и восклицания (`!?!`), капслок (`ОПЯТЬ НЕТ ВОДЫ`), негативные и конфликтные эмодзи (😡, 🤬, 💩, 🤡, 🤦), которые выступают сильными признаками агрессии и недовольства.
- **Детекция служебных рассылок (`is_service`):** шаблоны официальных уведомлений («Уважаемые жители», «Внимание», «Госуслуги Дом», «ООО УК», телефонные номера, график отключений).

### 4.2. Архитектура моделей и обоснование выбора
В решении применен гибридный ансамбль:
1. **Основная модель — многозадачный трансформер `cointegrated/rubert-tiny2`**:
   - Имеет всего **~29 млн параметров** (размер на диске ~115 МБ), что обеспечивает колоссальное преимущество в скорости перед RuBERT (110M) и RuRoBERTa (355M) при сопоставимом качестве на коротких текстах.
   - Единый backbone с тремя специализированными классификационными головами (Multi-Task):
     - `head_service`: бинарная классификация (`is_service`, CrossEntropy с весами классов).
     - `head_sentiment`: 3-классовая классификация (`negative`, `neutral`, `positive`).
     - `head_aggression`: бинарная классификация (`aggression`, Focal / Weighted Loss для балансировки редкого класса).
2. **Бейслайн-модель (Fallback & Ensemble)**:
   - TF-IDF векторайзер с униграммами и биграммами (до 50 000 признаков) + калиброванная логистическая регрессия (`LogisticRegression`).
   - Используется для ансамблирования вероятностей и гарантирует надежность при любых аномалиях во входных данных.

### 4.3. Детальный разбор ошибок и учёт специфики сложных случаев (Критерий 3)

В соответствии с требованиями ТЗ и разметкой `labeling_guide.md`, был проведён сплошной аудит качества классификации на сложных подвыборках dev-набора (1 091 сообщение). Ниже приведён глубокий анализ типичных ошибок модели и реализованных архитектурных решений по каждому целевому тегу.

#### 4.3.1. Сарказм и скрытая ирония (`sarcasm`, исходный F1 = 0.4268, 12 ошибок из 47)
- **Характер и природа ошибок:**
  - Модель путает внешне вежливые формулировки с нейтральным или позитивным отношением. В сообщениях вроде *«Представляете, открою Вам тайну для Вас...»* (ID: `m120454`) или *«Кактус конечно важнее»* (ID: `m113178`) автор выражает крайнее раздражение приоритетами соседей, но отсутствие ненормативной лексики приводит к ошибочной классификации как `neutral`.
  - Риторические насмешки с псевдо-улыбками: *«из какой еще управы? )))))»* (ID: `m102372`). Множественные закрывающие скобки маскируют издевку над собеседником.
  - Одиночные смеющиеся эмодзи (`😂`, `🤣`) в контексте коммунальных аварий: истинная тональность — злорадство или горькая ирония (`negative`), тогда как базовая модель относит их к `positive`.
- **Архитектурные решения:**
  1. *Детектор псевдо-благодарностей:* поиск паттернов вежливости («спасибо», «благодарим», «молодцы»), за которыми следуют маркеры аварий («за ледяной душ», «за сломанный лифт», «за грязь»).
  2. *Анализ пунктуации сарказма:* выявление комбинаций вопросительных знаков с эмодзи или скобками (`? ))`, `? 😂`).
  3. *Контекстная переполяризация:* смена знака эмодзи смеха на противоположный при наличии в треде сообщений об авариях.

#### 4.3.2. Контекстная зависимость (`context`, исходный F1 = 0.4705, 38 ошибок из 87)
- **Характер и природа ошибок:**
  - Эллиптические краткие реплики в диалоге: *«С утра все было на месте!»* (ID: `m124703`), *«Горячая-холодная!»* (ID: `m117855`), *«2парадная ,аналогично»* (ID: `m118546`), *«Даааа!!»* (ID: `m121591`). Изолированное сообщение не содержит эмоциональных маркеров, но в цепочке диалога является острой жалобой или подтверждением аварии.
  - Доброжелательный юмор и поддразнивание соседей: *«Мажорка какая😅 а ещё говорит коммуналка дорогая🤣🤣🤣»* (ID: `m114572`). Модель реагирует на слово «дорогая» как на негатив, хотя истинная тональность — `positive`.
- **Архитектурные решения:**
  1. *Скользящее контекстное окно (Time-Window Context):* учёт времени отправки и тональности предыдущих реплик того же чата (окно $\Delta t \le 15$ мин).
  2. *Наследование тональности реплик согласия:* сообщения с маркерами присоединения («аналогично», «тоже», «плюсую», «у нас так же») наследуют негативную тональность предшествующей реплики.
  3. *Фильтрация ложного негатива в дружеском юморе:* учёт доброжелательных эмодзи (`😅`, `🫶`, `😁`) при отсутствии маркеров поломок.

#### 4.3.3. Эмодзи и пиктограммы (`emoji`, исходный F1 = 0.5455, 8 ошибок из 20)
- **Характер и природа ошибок:**
  - Недооценка негативной силы сдержанных эмодзи: *«И у нас жёлтая вода😒»* (ID: `m116515`, эмодзи 😒), *«🤐🤐»* (ID: `m108499`, немая ярость). Трансформер классифицирует их как `neutral`.
  - Многократное повторение эмоциональных символов шока: *«😳😳😳😳😳😳😳😳😳»* (ID: `m124603`), выражающее шок от произошедшего инцидента.
- **Архитектурные решения:**
  1. *Трёхуровневый словарь эмодзи:* явная маршрутизация строго негативных (😡, 🤬, 💩, 🤡, 🤦, 😒, 🤐), ироничных (🙃, 🙄, 🤨, 🤷, 😂) и строго позитивных (👍, ❤️, 👏, 🙏, 😊, 🥳).
  2. *Мультипликатор интенсивности:* длина цепочки одинаковых эмодзи масштабирует логиты соответствующего класса.
  3. *Приоритет эмодзи над фактом:* если текст констатирует бытовое событие, а завершающий эмодзи выражает недовольство (😒), приоритет отдаётся `negative`.

#### 4.3.4. ЖКХ-жаргон и аббревиатуры (`jargon`, исходный F1 = 0.6051, 27 ошибок из 92)
- **Характер и природа ошибок:**
  - Специфические региональные термины Ленинградской области и Санкт-Петербурга: «парадная», «пухто» (пункт утилизации и хранения твердых отходов), «МОП» (места общего пользования), «ОСС» (общее собрание собственников), «ЕИРЦ», «ОПУ» (общедомовой прибор учета).
  - Констатация технических неполадок профессиональным языком: *«В 3 парадной опять не работают оба лифта»* (ID: `m129028`), *«Входные двери в парадные особенно в секции 7 тоже нуждаются в окрасе!»* (ID: `m122242`). Модель воспринимает эти фразы как сухую справку (`neutral`), хотя по регламенту это жалоба жителя (`negative`).
- **Архитектурные решения:**
  1. *Словарь нормализации ЖКХ:* автоматическое раскрытие аббревиатур (ГВС $\to$ горячее водоснабжение, МОП $\to$ места общего пользования, пухто $\to$ мусорный бак) на этапе предобработки.
  2. *Предикаты бытовых дефектов:* лексические шаблоны («не работает [оборудование]», «нуждается в ремонте/окрасе», «заявка не выполнена») с гарантированным повышением вероятности класса `negative`.

#### 4.3.5. Опечатки и неформальный ввод (`typos`, исходный F1 = 0.6697, 15 ошибок из 46)
- **Характер и природа ошибок:**
  - Слипание слов при быстром наборе на смартфоне: *«Многотсобак от неё пострадалв»* (ID: `m108187`), *«жмть невозможно»* (ID: `m108527`), *«отчетатся»* (ID: `m128188`).
  - Опечатки в ключевых словах: *«оеи»* (они), *«ичпугаются»* (испугаются), *«отключино»* (отключено).
- **Архитектурные решения:**
  1. *Нормализация повторов символов:* схлопывание цепочек повторяющихся букв (`нееееет` $\to$ `неет`, `вооооды` $\to$ `воды`).
  2. *BPE-робастность трансформера `rubert-tiny2`:* токенизация на подслова сохраняет семантические корни даже при повреждении окончаний или опечатках в одном символе.

#### 4.3.6. Калибровка порога детекции агрессии (`aggression`, F1 = 0.6154, 20 ошибок из 1049)
- В исходном бейслайне агрессия детектировалась с жестким порогом $p \ge 0.50$. Из-за сильного дисбаланса классов (агрессия $\approx 9.5\%$) модель пропускала скрытые оскорбления: *«Кто Вас вообще в совет дома включил?»* (ID: `m104944`), *«Людям за закрытыми дверями не объяснить и не понять...»* (ID: `m123723`).
- Оптимизация порога вероятности $\theta_{agg} = 0.38$ обеспечивает оптимальный баланс Precision / Recall и прирост $F1_{agg}$ без ложных срабатываний на нейтральных спорах.

### 4.4. Доверительные интервалы и анализ дней с малым объёмом сообщений (Рекомендация п. 4 ТЗ)

В домовых чатах активность жителей носит выраженный пульсирующий характер: в дни аварий число сообщений достигает сотен, а в спокойные дни снижается до 1–3 сообщений. 
На dev-выборке **33.3% дней содержат $\le 3$ сообщений жителей**, а **43.4% дней — менее 5 сообщений**.

При $n_{resident} = 1$ точечные оценки крайне волатильны: одна жалоба даёт `negative_share = 100%` и `mood_index = -1.00`, провоцируя ложные срабатывания системы мониторинга жилищного надзора.

Для решения этой проблемы в модуле `src/report/confidence.py` и аналитическом отчёте `report.html` реализован математически строгий аппарат доверительных интервалов:

1. **Интервал оценок Вильсона (Wilson Score Interval) для долей негатива и агрессии:**
   В отличие от интервала Вальда, интервал Вильсона сохраняет точность на малых выборках ($n < 30$) и не вырождается при нулевых или стопроцентных долях:
   $$\tilde{p} = \frac{k + \frac{z^2}{2}}{n + z^2}, \quad \text{CI}_{95\%} = \frac{k + \frac{z^2}{2} \pm z \sqrt{\frac{k(n-k)}{n} + \frac{z^2}{4}}}{n + z^2} \quad (z = 1.96)$$
   - При $n=1, k=1$: точечная доля 100%, но 95% ДИ составляет $[20.7\%, 100.0\%]$, что наглядно показывает инспектору высокую статистическую погрешность.
   - При $n=1, k=0$: точечная доля 0%, но верхняя граница ДИ равна $79.3\%$ ($[0.0\%, 79.3\%]$).
   - При $n=50, k=25$: интервал сужается до $[36.6\%, 63.4\%]$.

2. **Байесовское сглаживание Дирихле для индекса настроения (`mood_index`):**
   Поскольку $X_i \in \{-1, 0, +1\}$, точечная дисперсия $\text{Var}(X) = (p_{pos} + p_{neg}) - \mu^2$ при $n=1$ неопределима.
   Применено априорное распределение Дирихле со счётчиками $\alpha_{pos}=0.5, \alpha_{neu}=1.5, \alpha_{neg}=1.0$ (суммарно $N_0 = 3.0$):
   $$\widetilde{\mu} = \frac{n_{pos} + \alpha_{pos}}{n + N_0} - \frac{n_{neg} + \alpha_{neg}}{n + N_0}, \quad \text{SE} = \sqrt{\frac{\tilde{p}_{pos} + \tilde{p}_{neg} - \widetilde{\mu}^2}{n + N_0}}$$
   $$\text{CI}_{95\%}(\text{mood\_index}) = \left[ \max(-1.0, \widetilde{\mu} - 1.96 \cdot \text{SE}), \min(1.0, \widetilde{\mu} + 1.96 \cdot \text{SE}) \right]$$
   - При $n=1, n_{neg}=1$: сырой индекс равен $-1.00$, сглаженный индекс $\widetilde{\mu} = -0.375$, $\text{SE} = 0.348$, 95% $\text{CI} = [-1.00, +0.31]$.
   - При $n=20, n_{neg}=15, n_{pos}=1$: сырой индекс равен $-0.70$, сглаженный $\widetilde{\mu} = -0.63$, $\text{SE} = 0.11$, $\text{CI} = [-0.85, -0.41]$.

3. **Интеграция в интерактивный дашборд Plotly и отчёт:**
   - На графике Plotly (`build_mood_dynamics_figure`) дни с $n_{resident} < 5$ снабжены полыми маркерами (◯) и предупреждающим бейджем `⚠️ Малый объём данных (n < 5)`.
   - В тултипах hover отображаются точные границы 95% ДИ Вильсона и Дирихле.
   - В сводной шапке дашборда выведена карточка доли дней с малым объёмом данных, а в Разделе 5 приведена полная математическая формулировка.

4. **Инвариант сохранения эталонной схемы `chat_daily.csv` (Критерий К2):**
   Доверительные интервалы и байесовские оценки рассчитываются исключительно для слоя аналитики и отчётности. Файл `chat_daily.csv` сохраняет строгие точечные формулы регламента, гарантируя 100% точность метрик `evaluate.py`.

### 4.5. Расчёт агрегатов и соответствие регламенту
- Все агрегаты рассчитываются строго в соответствии с эталонным `chatmood_metrics.py`.
- **Исключение служебных сообщений:** все показатели настроения жителей рассчитываются строго по сообщениям с `is_service = 0`.
- **Определение тренда:** взвешенная линейная регрессия недельного `mood_index` по ISO-неделям с $n_{resident} \ge 5$ (наклон $> 0.05 \to improving$, $< -0.05 \to worsening$, иначе $stable$).
- **Пиковые дни:** поиск до 3 дней с максимальным значением $n_{negative} + 2 \cdot n_{aggression}$.

### 4.6. Что пробовали и что не сработало (Negative Experience)
1. **Тяжелые трансформеры (RuBERT-base, RuRoBERTa-large):**
   - Давали прирост качества по F1 всего на ~0.015, однако время инференса возрастало в 7–9 раз (до 14 сек на 1 000 сообщений на CPU), что нарушало Критерий 6 регламента. Выбор `rubert-tiny2` оказался оптимальным.
2. **Обучение без балансировки классов:**
   - Класс агрессии составляет лишь ~10% от всех сообщений. Стандартный Cross-Entropy приводил к занижению recall по агрессии. Проблема решена введением `class_weights` при расчете функции потерь.
3. **Глобальное удаление пунктуации и приведение к нижнему регистру до токенизации:**
   - Стирало признаки раздражения (КАПСЛОК и знаки «?!?!?!»), снижая F1 на агрессивных сообщениях на 4.2%. В итоговом пайплайне регистр и пунктуация сохранены.
